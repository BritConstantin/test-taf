Deferred risks and rationale:

- Real provider search-index changes and production HTTP integration: deterministic fixtures cannot establish them; opt-in live smoke is omitted to keep default tests offline and precise. This is not consumer-driven provider contract verification.
- Marine/wave suitability, venue availability, snowpack and safety: require new data and product scope. Current model makes no such promise.
- Every threshold combination, missing optional region permutations, every provider status and every malformed payload: representative risks are covered; exhaustive matrices would overwhelm a take-home. IANA timezone usability and invalid upstream values are specified, but not every malformed variant is injected.
- Provider resolution's missing-ID semantics depend on a documented observed upstream response. Other upstream 400 errors must remain provider failures; exhaustive upstream error taxonomy is deferred.
- Parallel isolation, full network egress enforcement and future SUT startup in CI: require actual runtime/integration choices. This submission specifies one local serial topology.
- Best-day-per-activity sorting, postal/advanced search, caching/retries, auth, rate limiting, persistence, security/load suites and UI: no ticket requirement; intentionally omitted.
