# Official references checked during implementation

Checked on 2026-10-26. These establish provider/tool mechanics, **not** the proposed product scoring model. No deterministic acceptance test calls these sources.

- [Open-Meteo geocoding documentation](https://open-meteo.com/en/docs/geocoding-api): search shape/parameters, normalized prefix and case/diacritic behaviour, omitted optional metadata, and ID resolution through `/v1/get`. No substring/typo guarantee is assumed. The two-character `Bø` candidate metadata was checked with a read-only search; its fixture is a controlled subset, not a claim about global result order. A read-only request to `https://geocoding-api.open-meteo.com/v1/get?id=999999999` observed HTTP 400 with `error: true` and `reason: "Location ID not found."`; this is an observed mapping example, not a universal promise about upstream errors.
- [Forecast documentation](https://open-meteo.com/en/docs): chosen daily fields and units, local time/date parameters and response arrays. No weather-code input is used, so the suite makes no WMO clear-sky/storm assertions. Synthetic values retain the provider shape; they are not recorded forecasts or claims about real October weather.
- [Open-Meteo JSON writer](https://github.com/open-meteo/open-meteo/blob/main/Sources/App/Helper/Writer/JsonWriter.swift): numeric non-finite values serialize as null. Required nulls are rejected by the proposed product policy, never treated as zero. Optional geocoding metadata omission and required forecast numeric nulls are different cases.
- [Cucumber-JS 13.3.0 configuration](https://github.com/cucumber/cucumber-js/blob/v13.3.0/docs/configuration.md) and [support API](https://github.com/cucumber/cucumber-js/blob/v13.3.0/docs/support_files/api_reference.md): compiled support loading, serial execution, hooks and reporting. Runtime binding checks and five infrastructure probes supplement documentation checks.
- [Ajv reference resolution](https://ajv.js.org/guide/combining-schemas.html) and [OpenAPI nullable support](https://ajv.js.org/json-schema.html#nullable-openapi): original component references are retained instead of competing public schemas. [Swagger Parser API](https://apidevtools.com/swagger-parser/): OpenAPI structural validation.
- [Node release support](https://nodejs.org/en/about/previous-releases): Node 24 is an LTS line. Installed runtime was 24.19.0 and is pinned. Package metadata from the npm registry verified Cucumber 13.3.0's Node 24 support. TypeScript 6.0.3 satisfies typescript-eslint 8.72.0's `<6.1.0` peer range; latest TypeScript 7 was deliberately not selected. Exact resolved versions are in the lockfile.
- Official [checkout](https://github.com/actions/checkout), [setup-node](https://github.com/actions/setup-node), [upload-artifact](https://github.com/actions/upload-artifact) READMEs were checked for their current v7 usage. Workflows have not run on GitHub.
